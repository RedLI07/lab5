# Практическая работа № 5 — вариант 19 → 9

По уточнению пользователя используется **вариант 9** из `5 (1).pdf` (в PDF только варианты 1–10).
Приложение — HTTP-сервис проверки диска, продолжение практики № 3.

## Запуск

Нужны Python 3.12+ (тесты без сторонних библиотек), Git и Docker с Compose.
Из каталога `lab5`:

```sh
python3 -m unittest discover -s tests -v
cp env.example .env
docker compose build
docker compose up -d --wait
curl http://127.0.0.1:8219/health
curl http://127.0.0.1:8219/disk
docker compose logs --tail 50
docker compose stats --no-stream
```

Ответ `/disk` содержит общий и свободный объем диска **тома контейнера**, версию,
сообщение и счетчик запросов. `/health` не изменяет счетчик, неизвестный маршрут возвращает 404.
Сервис доступен только с локального компьютера; авторизация для учебного сервиса не требуется.
Данные сохраняются в именованном томе `practice5-v19_disk-data`.

## Полная проверка практики

```sh
python3 scripts/deploy_check.py
```

Сценарий пересоздает только проект `practice5-v19`: проверяет исходные 96 MiB,
развертывает 128 MiB, создает резервную копию при остановленном сервисе,
восстанавливает ее в `restored`, моделирует отказ при 6 MiB,
возвращает предыдущие 96 MiB и завершает на 128 MiB.
Счетчик сохраняется; повторный запуск увеличивает его. Команды и результаты записываются
с временем UTC в `evidence/deployment.jsonl`, приемка — в `evidence/acceptance.json`.
Рабочие данные и резервные копии исключены из Git.

## Материалы

- `REPORT.md` — отчет по пяти заданиям, паспорт и акт.
- `Отчет_практика5_вариант19.docx` — Word-отчет с восемью снимками и подписями.
- `screenshots/` — снимки браузера со страницами фактического вывода команд; `capture.py` повторяет сбор.
  Снимки отказа и приемки используют сохраненные файлы `evidence/`, остальные команды выполняются при сборе.
- `RUNBOOK.md` — команды развертывания, наблюдения и отката.
- `CHANGELOG.md` — состав версии v1.0.0.
- `evidence/` — фактические результаты проверок.

Остановка: `docker compose down`. Эта команда сохраняет том.
Удаление тома (`down -v`) удаляет рабочие данные и для обычного завершения не требуется.

Локальный Git-репозиторий: ветка `release`, аннотированная метка `v1.0.0`.
