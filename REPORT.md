## Задание 1. Паспорт приложения и платформы

Выбрано собственное приложение из практики № 3 — disk-service.
Назначение: показать свободное место на диске, где расположен том данных,
и сохранить счетчик запросов. Пользователи — студент и администратор учебной среды.
Вход: HTTP GET `/disk`, `/health`. Выход: JSON с емкостью, свободным местом,
версией и счетчиком; HTTP 404 для неизвестного пути, 503 при повреждении состояния.
Согласование приложения с преподавателем остается организационным действием студента.

|---|---|

| Целевая Linux-среда | Docker Desktop VM, ядро 6.12.69-linuxkit |
| Архитектура Engine / образа | aarch64 / arm64 |
| Ресурсы Linux VM | 10 CPU, 7.65 GiB RAM |
| Место на диске хоста | 228 GiB всего, 30 GiB доступно на момент инвентаризации |
| Docker Engine / Compose | 29.2.1 / v5.0.2 |
| Версия приложения / Python образа | v1.0.0 / 3.12.13 |
| Лимит контейнера | 128 MiB RAM, память+swap 128 MiB (swap отключен), 0.5 CPU, 64 PID |

| Порт | 127.0.0.1:8219 → 8000/tcp |

| Сеть / том | practice5-v19_default / practice5-v19_disk-data |
| Данные / журналы | /data/state.json / stdout и stderr, ротация 2 × 5 MiB |
| Ответственный | Студент — владелец учебного проекта |

Физическое оборудование и питание находятся под управлением владельца хоста;
GPU и внешняя БД этому приложению не нужны. Сервис слушает только localhost.
Критерии приемки: healthy, рабочий `/disk` под лимитом 128 MiB, сохранность счетчика,
резервная копия, наблюдаемый отказ, восстановление после возврата лимита.

## Задание 5. Наблюдение, отказ и эксплуатационный отчет

Healthcheck обращается к `/health` каждые 5 секунд, timeout 3 секунды,
start-period 5 секунд, retries 3. Проверяются чтение состояния и доступ к диску.
Журналы просматриваются через `docker compose logs`, состояние — через inspect,
ресурсы — через stats. Установлена политика unless-stopped.

**Журнал события:**

1. 2026-11-16T18:00:01.137287048Z — запуск того же образа и тома с лимитом 6 MiB,
   без swap и без автоматического перезапуска экспериментального контейнера.
2. 2026-11-16T18:00:01.195067756Z — завершение: Status=exited,
   ExitCode=137, OOMKilled=True.
   Причина: памяти недостаточно для запуска Python-сервиса. При OOM процесс
   был убит ядром, поэтому файл stdout/stderr эксперимента пуст; причина
   подтверждена полем OOMKilled в `evidence/failure-state.json`.
3. Возвращен прежний лимит 96 MiB, получен healthy и подтверждены данные.
4. Возвращен штатный лимит 128 MiB, получен healthy, сняты stats и журналы.

Данные пережили остановку, замену контейнера и учебный OOM. Примерная память
в финальном снимке — 13.47 MiB из 128 MiB. Это краткая функциональная приемка,
а не длительное нагрузочное испытание; оценка вместимости по пользователям не проводилась.
